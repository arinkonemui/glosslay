# tools/nmt-eval — ローカルNMT の訳文と速度の計測

**製品と同じコード（`Glosslay.Core` の `LocalNmtTranslator`）を通して**測る道具。
`tools/nmt-convert` の Python 側は元モデルの挙動を見るためのもので、役割が違う。

---

## 実行

```bash
dotnet run --project tools/nmt-eval/NmtBench
```

既定では `tools/nmt-convert/out/elan-en-ja/int8` を見る。引数でモデルを指定できる。

```bash
dotnet run --project tools/nmt-eval/NmtBench -- <モデルのディレクトリ>
```

| 引数 | 何をするか |
|---|---|
| `--tokens` | 分割と id だけを出す。翻訳しない |
| `--batch` | 行をまとめて 1 回で流す（既定は 1 件ずつ） |
| `--fallback` | **FR-TRN-06 の切り替えを確かめる。**翻訳の計測はしない |
| `--selection` | **FR-TRN-17 の選択（自動 / クラウドのみ / ローカルのみ）を確かめる。**モデルも読まない |
| `--cache` | **FR-TRN-09 の使い回しを確かめる。**2 回訳して、2 回目が 0ms かつ同じ訳文かを見る |
| `--numbers` | **FR-TRN-08 の数値照合を確かめる。**モデルを読まない |
| `--services` | **横断インターフェースの配線を確かめる**（ゲート・遠隔設定・広告・入力）。モデルを読まない |
| `--watch` | **自動監視の守りを確かめる**（前面・差分・上限）。モデルを読まない |
| `--dwell` | **カーソル静止の判定を確かめる**（時計を進めて見る）。モデルを読まない |
| `--profiles` | **プロファイルの当て方と上限を確かめる**（FR-CFG-01〜03）。モデルを読まない |
| `--languages` | **訳文の言語の扱いを確かめる**（FR-CFG-01 / FR-TRN-03）。モデルを読まない |
| `--usage` | **使用量の数え方と文面を確かめる**（RULES.md 🟡-8）。モデルを読まない |

### `--fallback`

必ず失敗するバックエンドを相手に、`LineTranslation` が切り替えるかを見る。
**クラウドの失敗を待たずに確かめられる。**

```
=== FR-TRN-06 切り替えの確認 ===
    混雑（HTTP 503）           切替 した   （期待 する）  状態 Succeeded
    キー未登録                  切替 しない  （期待 しない）  状態 NotConfigured
    混雑だが原文が中国語             切替 しない  （期待 しない）  状態 Busy
```

**切り替えてはいけない場合を必ず含めること。**

| 場合 | なぜ切り替えないか |
|---|---|
| キー未登録 | 設定の誤りを隠すと「登録したのに効いていない」ことに気づけない |
| **原文が中国語** | 同梱モデルは英→日のみ。渡すと**流暢な出鱈目**が出る（RULES.md 🟡-1 の承認済みの例外） |

### `--selection`

「3 つの選択 × キーの有無」の組み合わせを表のまま検査する。**モデルを読まないので一瞬で終わる。**

```
  自動・キーあり                クラウド       ローカル       OK
  自動・キーなし                ローカル       なし         OK
  クラウドのみ・キーなし            クラウド       なし         OK
```

**RULES.md 🟡-1「既定はローカル、クラウドは任意のアップグレード」がここで崩れうる。**
選択肢が増えたので、順序が逆になっていないかを機械的に見る。
規則は `TranslatorSelection` にあり、画面からは切り離してある。

### `--profiles`

**当ててはいけないものが当たることが一番危ない。**
自動適用は前面のウィンドウを見て黙って設定を差し替えるため、別のゲームに当たると
「設定が勝手に変わった」としか見えない。

```
=== 使えないクラス名（2026-10-11 実測）===
    WPF のクラス名は変わるものと判る                           OK
=== 複数が当たるとき（先に登録したものを優先）===
    先に登録した方が勝つ          OK  ← クラス名だけの登録は後続を食う
```

| 押さえている点 | なぜ |
|---|---|
| 対象が空のプロファイルは何にも当たらない | 放っておくと**全部のウィンドウに当たる** |
| WPF のクラス名を弾く | `HwndWrapper[…;;<GUID>]` は**起動ごとに変わる**（実測） |
| 置き換えは上限に数えない | 上限は「持てる数」であって「保存した回数」ではない |
| 壊れた JSON で落ちない | 他の人から貰う前提（RULES.md 🟡-6） |

**実物の `profiles.json` は触らない。**別のファイル名を渡して検査し、最後に消す。

### `--usage`

**課金に直結する数字なので、数え違いが一番こわい。**

| 押さえている点 | なぜ |
|---|---|
| 失敗も呼び出しに数える | **通信は起きている。**失敗したから無かったことにはならない |
| ローカルをクラウドに混ぜない | 合算すると「使った」の意味（課金されるか）が分からなくなる |
| 見るだけでは日を作らない | 使わなかった日の空の記録を残す意味がない |
| 62 日より古い記録は落とす | **使用量の記録それ自体が膨らむのは筋が通らない** |
| 余裕があれば残りを出さない | オーバーレイの隅は狭い。**減ってきたときだけ**添える |

**実物の `usage.json` は触らない。**別のファイル名を渡して検査し、最後に消す。

### `--languages`

**一番危ないのは「訳せないのに成功して返る」こと。**
同梱のモデルは英→日のみなので、英語を訳文の言語に選んで訳させると
**日本語が出て、しかも成功として返りうる**。

**存在しないモデル置き場を渡して、判定の順序だけを見る。**

```
    日本語は言語では断らない          OK  ← NotConfigured（モデルが無いので止まる）
    英語はモデルの有無より先に断る      OK  ← Unsupported
```

モデルを置いてもその言語は訳せないので、**「モデルが無い」より先に断る**のが正しい。
`Unsupported` では FR-TRN-06 の切り替えが働かないことも、ここで押さえている。

## `--tokens` が要る理由

**トークナイザの id の引き方を間違えても、例外にならない。**

Marian は `.spm` で「分割」だけを行い、id は `vocab.json` で引く。
`EncodeToIds` の id をそのまま使うと別の語になり、**意味の通らない訳文が静かに出る**。
2026-09-27 に `opus-mt-tc-big-zh-ja` で実際に踏んでいる（「勝利の漫画は、yにインポートされた後、」）。

疑わしいときは Python 側と突き合わせる。

```bash
# C# 側
dotnet run --project tools/nmt-eval/NmtBench -- <モデル> --tokens

# Python 側
cd tools/nmt-convert
./.venv/Scripts/python.exe -c "
from transformers import AutoTokenizer
tok = AutoTokenizer.from_pretrained('out/elan-en-ja/int8')
print(tok('Attack Power')['input_ids'])
"
```

2026-10-01 に 16 文で突き合わせ、**不一致 0 件**を確認している。

## 1 件ずつが既定

**まとめて流すと、訳文が同じ画面にある他の行に左右される。**
短い行はバッチの最長行に合わせて詰め物で埋められ、その分だけ数値がわずかに動く。
貪欲探索は僅差の語を選び直すため結果が変わる。
**実装の誤りではなく、Python 側でも同じように変化する。**

速度の利点は実際の画面ではほぼ無い（2026-10-01 実測・4 スレッド）。

| 入力 | まとめて | 1 件ずつ |
|---|---|---|
| カード 1 画面 11 件（長短が混ざる） | 493 ms | **510 ms** — 差 3% |
| 長文 3 件（長さが揃う） | 222 ms | 331 ms |
| 短い 2 件 | 30 ms | 29 ms |

まとめた場合は**全行が終わるまで回る**ため、長さが混ざると終わった行の分まで
計算し続けて利点が消える。3% と引き換えに「同じ原文がいつも同じ訳になる」ことを選んでいる。

> **1 件ずつなら Python の実装と訳文が完全に一致する。**
> 2026-10-01 に長文 3 件で一字一句の一致を確認した。回帰を機械的に確かめられる。

## 訳文の質は人が読む

一致度のような数字にはしていない。P0-7 と同じで、**数値の欠落なのか語尾の違いなのかは
人でないと分けられない**ため。見るべき点。

| 観点 | なぜ |
|---|---|
| **数値が保たれているか** | RULES.md 🟡-7。`HP 270` `2枚` `60気圧` が残ること |
| **意味が反転していないか** | `prevent all damage` を「与える」と訳していないか。長文で起きやすい |
| 固有名詞 | `Tera` →「寺」のような誤りは用語集（FR-TRN-11）で埋める前提 |

## 既知の落とし穴

| 事象 | 内容 |
|---|---|
| `.spm` を書き換えていないと落ちる | Marian は `bos_id = -1`。`Microsoft.ML.Tokenizers` が `IndexOutOfRangeException` を投げる。`tools/nmt-convert/patch_spm.py` が 0 に書き換える |
| 短い断片は訳が荒い | `30 damage` →「30ヶ所」。数値は保たれるが語が落ちる。行結合（FR-TRN-10）で文にしてから渡すこと |
| モデルは配布物に同梱しない | CC BY-SA 4.0 の「並べて配る」立場を保つため、実行ファイルへ埋め込まない（`tools/nmt-convert/README.md`） |
